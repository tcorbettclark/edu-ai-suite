# Browser language-model test build

This directory is a prototype for the 12b widget: tiny LSTMs trained on public-domain
books and on TinyStories, exported as JSON, and run in JavaScript. It is not part of the
published example set; it lives in a subdirectory so the existing `examples/*.py`
contract is unchanged.

See `HANDOFF.md` for the current state, the corpus table and the next training step.

## What is here

- `corpus.py` — the selected corpus (`BROWSER_LM_CORPUS`), its source details, and the
  body extraction that removes the Gutenberg wrapper and boilerplate.
- `train_export.py` — trains the character-level and word-level LSTMs, keeps the random
  initial weights plus epochs 5, 20 and 50, and writes `out/<corpus>/char.json` and
  `out/<corpus>/word.json`. It prints loss and perplexity every epoch, and training and
  validation token accuracy at every saved checkpoint.
- `make_reference.py` — rebuilds each checkpoint and writes greedy reference outputs to
  `out/<corpus>/reference.json`.
- `manifest.py` — writes the run manifest from the exported `char.json` and
  `word.json`.
- `compact_export.py` — writes the browser files:
  `out/<corpus>/char.compact.json` (float32) and `out/<corpus>/word.compact.json`
  (int8 with one scale per matrix row).
- `lm.js` — browser/Node inference: tokenizer, LSTM forward pass, temperature sampling,
  and next-token probabilities.
- `test_infer.js` — checks every greedy output against the Python reference.
- `index.html` — a stepwise browser demo: show the next-token distribution after every
  token, sample one, undo, or click a candidate to force it. Bars and treemap views.

The corpus is selected once, by the `BROWSER_LM_CORPUS` environment variable. The
default is `dorian_gray`; the alternatives are `happy_prince` and `tiny_stories`.

## Happy Prince baseline

Corpus: 86,120 characters, 84,759 char tokens, 20,132 word tokens, 2,409 word types.

| model | parameters | checkpoint | validation loss |
|---|---:|---:|---:|
| char | 26,406 | 5 | 2.038 |
| char | 26,406 | 20 | 1.689 |
| char | 26,406 | 50 | 1.584 |
| word | 169,065 | 5 | 5.570 |
| word | 169,065 | 20 | 5.027 |
| word | 169,065 | 50 | 4.964 |

Browser assets:

- `char.compact.json`: 566 KB, float32, exact.
- `word.compact.json`: 932 KB, int8 with per-row scales; greedy outputs unchanged.
- Total: about 1.5 MB.

Inference in Node for 48 generated tokens is about 10–40 ms per checkpoint. The local
browser page loaded both models and produced a first output in about 75 ms.

All greedy outputs match the Python reference at every checkpoint for both tokenizations.

### Sample outputs

Word, epoch 50, temperature 0.7, JS seed 1:

> the swallow flew over the city, the Nightingale] asked the Miller of the Frog, and the King was a great beautiful steeple.

Char, epoch 50, temperature 0.7, JS seed 0:

> the swallow flew over the city Hait is the lightinge as the rived out in the m

The word model is the more convincing demo. The char model is useful for showing the
gibberish-to-fragments progression, but it is not going to write clean prose.

## Dorian Gray run

The larger corpus is *The Picture of Dorian Gray*: 429,022 characters, 96,168 word
tokens and 7,393 word types. It is roughly five times the Happy Prince data.

| model | parameters | checkpoint | train loss | val loss | train acc | val acc |
|---|---:|---:|---:|---:|---:|---:|
| char | 26,892 | 5 | 1.822 | 1.794 | 44.6% | 48.1% |
| char | 26,892 | 20 | 1.563 | 1.589 | 51.3% | 53.9% |
| char | 26,892 | 50 | 1.462 | 1.528 | 54.2% | 55.6% |
| word | 493,025 | 5 | 5.018 | 5.204 | 17.9% | 18.8% |
| word | 493,025 | 20 | 3.869 | 5.052 | 26.5% | 22.7% |
| word | 493,025 | 50 | 3.028 | 5.785 | 36.5% | 22.8% |

The word model reaches its best validation loss around epoch 12 (4.961) and then
overfits. The late checkpoint is still useful for showing that training accuracy keeps
rising while validation accuracy stalls, but it is not the best text generator.

Browser assets after `compact_export.py`:

- `char.compact.json`: 577 KB, float32, exact.
- `word.compact.json`: 3.37 MB, int8 with one scale per row; greedy outputs unchanged.
- Total: about 3.95 MB raw, about 2.67 MB gzipped.

Run `train_export.py` once and watch the epoch lines for training/validation loss,
perplexity and token accuracy. The script also prints samples at each checkpoint.

## TinyStories run

TinyStories is a Microsoft Research dataset of synthetic short stories generated by
GPT-3.5 and GPT-4 using a small vocabulary. The corpus here is a fixed subset of the
first 500 complete stories from the train split: 400,219 cleaned characters.

| | Dorian Gray | TinyStories |
|---|---:|---:|
| cleaned characters | 429,022 | 400,219 |
| char vocab | 76 | 75 |
| char tokens | 421,062 | 393,125 |
| word vocab | 7,393 | 3,729 |
| word tokens | 96,168 | 90,441 |
| char parameters | 26,892 | 26,811 |
| word parameters | 493,025 | 254,865 |

The point of the comparison is the word vocabulary: almost the same number of
characters, but less than half the word types and less than half the word-model
parameters.

Run it with:

```bash
BROWSER_LM_CORPUS=tiny_stories uv run python examples/browser_lm/train_export.py
BROWSER_LM_CORPUS=tiny_stories uv run python examples/browser_lm/make_reference.py
BROWSER_LM_CORPUS=tiny_stories uv run python examples/browser_lm/compact_export.py
node examples/browser_lm/test_infer.js tiny_stories
```

Then open `http://127.0.0.1:8123/?corpus=tiny_stories`.

## What the test shows

- Offline training + JS inference is feasible and fast.
- Happy Prince fits in about 1.5 MB; Dorian Gray is about 3.95 MB raw, 2.67 MB gzipped.
- The word model overfits early on both Wilde corpora: training loss keeps falling
  while validation loss rises. Dorian's best validation loss is around epoch 12.
- The char model keeps improving through epoch 50 on Dorian.
- EOS often dominates the next-token distribution at a sentence end. The stepwise demo
  shows the distribution **before** generation and labels EOS as `end`.
- The most interesting visual is the next-token distribution itself, as in the
  limerick/N-gram widget, not a big generated paragraph.
- The demo defaults to the character model with `the port`, and the word model with
  `the portrait`, for the Dorian Gray corpus.

## Run it

```bash
cd edu-ai-suite
uv run python examples/browser_lm/train_export.py
uv run python examples/browser_lm/make_reference.py
uv run python examples/browser_lm/compact_export.py
node examples/browser_lm/test_infer.js dorian_gray

cd examples/browser_lm
python3 -m http.server 8123
# open http://127.0.0.1:8123/
```

To build another corpus, prefix every Python step with its name:

```bash
BROWSER_LM_CORPUS=happy_prince uv run python examples/browser_lm/train_export.py
BROWSER_LM_CORPUS=happy_prince uv run python examples/browser_lm/make_reference.py
BROWSER_LM_CORPUS=happy_prince uv run python examples/browser_lm/compact_export.py
node examples/browser_lm/test_infer.js happy_prince
# open http://127.0.0.1:8123/?corpus=happy_prince
```
